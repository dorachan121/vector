# 企画・要件定義書 — VECTOR CASINO RESORT

## 1. 企画の背景

2030 年ごろの開業が見込まれる国内のカジノ（統合型リゾート）に触発され、**既存のカジノゲームの焼き直しではない、オリジナルのカジノゲーム**を作ることにしました。最初の版は 14 日間で VECTOR 1 ゲームを作り、その後、設計を全面的に作り直して 10 ゲームとストーリーモードを持つ現在の形にしています。

## 2. コンセプト

**「確率をすべて公開した、正直なカジノ」**

| 柱 | 内容 |
|---|---|
| オリジナルのゲーム | カード × ライン、ダイス × 決闘、天球儀 × ルーレットなど、10 のオリジナルのカジノゲーム |
| 数学的に正しいカジノ | すべての配当を検証し、**最善を尽くしてもハウスがわずかに有利**（RTP 約 95〜97%）になるよう設計。確率と RTP をすべて公開 |
| 遊ぶ理由をつくる | フロアの主に挑むストーリーモード（カジノ RPG）、デイリーミッション、ログインボーナス |
| 責任あるゲーミング | 遊戯用チップのみ・ガチャなし・テーブルリミット・リアリティチェック |

## 3. 対象ユーザー

| ペルソナ | 求めるもの |
|---|---|
| カジノゲームが好きな人 | ブラックジャックやポーカーとは違う、新しい駆け引き |
| 確率・戦略を考えるのが好きな人 | 腕で RTP が変わるスキルゲームと、厳密な最善手の戦略ヒント |
| スマホでじっくり遊びたい人 | 物語・キャラクター・収集要素 |

## 5. 非機能要件

| 区分 | 要件 | 実現方法 |
|---|---|---|
| 公正さ | 乱数に偏りがない | 暗号論的乱数、Fisher–Yates のシャッフル、6 デッキのシュー |
| 公正さ | 成長要素で確率が変わらない | 経験値・ランク・コンプは賭けた額だけで貯まり、確率・配当に影響しない |
| 正確さ | 配当が設計どおり | 全列挙・動的計画法の厳密値とシミュレーションで検証し、CI で毎回確認 |
| 可用性 | 障害で固まらない・損をさせない | 1 ラウンドごとの例外捕捉と返金、中断した勝負・挑戦の返金 |
| 完全性 | セーブデータを守る | HMAC-SHA256 の改ざん検知、原子的な書き込み、1 世代バックアップ |
| 性能 | 60fps を保つ | AI の先読みをワーカースレッドで計算 |
| 互換性 | どの端末でも同じ見た目 | 基準解像度の枠を安全領域に合わせて拡大縮小、日本語フォントを同梱 |
| プライバシー | 個人情報を扱わない | 通信なし・権限なし（Android） |
| 保守性 | ルールを Unity なしで検証 | Core を Unity 非依存にし、.NET でテスト（137 件） |
| 配布 | Google Play | Android App Bundle、対象 API 36、ARM64（IL2CPP） |

## 6. 責任あるゲーミングへの配慮

| 項目 | 内容 |
|---|---|
| 遊戯用チップ | 現金・景品とは交換できないことをタイトル画面とストアに明記 |
| ガチャ | 置かない（確率で当たりが決まる有料・無料のくじはない） |
| リアリティチェック | 30 分ごとにプレイ時間とセッションの収支を知らせ、ロビーに戻るか続けるかを選べる |
| テーブルリミット | ゲームごとのミニマム・マキシマムとサイドベットの上限 |
| 補充 | 手持ちがミニマムを下回ったら遊戯用チップを補充（課金なし） |

## 7. 旧バージョン（2025 年 4 月）からの改善

| 旧バージョンの課題 | 対応 |
|---|---|
| 約 1,300 行の `gameManager` にすべての処理が集中 | Core（ルール）と Runtime（表示）に分け、1 ファイル 1 型・責務ごとのフォルダに再構成 |
| 残高チェックがなく、所持金がマイナスになる | `Bankroll` / `WagerSession` で残高・リミットを検証、セーブ値も範囲チェック |
| 偏りのあるシャッフル | Fisher–Yates ＋ 暗号論的乱数、6 デッキのシュー |
| 上手に打つとプレイヤーが大幅に有利（シミュレーションで RTP 160% 超） | ハウスウェイと「残り 2 種類の高い方」ルールで、最善手でもハウスエッジ約 3% |
| 引き分け時の精算ミス、毎フレームのセーブ | 精算を `Settlement` に一本化、セーブは配札時と精算時だけ |
| ゲームは 1 つだけ | 10 ゲームとストーリーモードを追加し、同じテーブルの土台（`CasinoDirector`）を共有 |
